## AI 창작 단편

2026-11-23에 똑독 AI가 새로 쓴 단편8편을 추가했어요. 각6쪽이며 저자는 ‘똑독 AI’로 표시해요. 기존 출간 작품의 본문을 옮긴 글이 아닌 AI 예시 창작물이에요. 새 작품의 초기 열람 수는0이에요.

- 목요일의 빈 의자 — 늦게 끝나는 근무와 독서 모임 사이의 일상 이야기.
- 화성행 반품 택배 — 잘못 배달된 빗소리를 따라가는 우주 택배 기사의 SF.
- 어제의 날씨를 팝니다 — 놓친 운동회와 유리병에 담긴 날씨를 둘러싼 판타지.
- 302호의 연습곡 — 벽 너머에서 반복되는 열두 마디의 사연.
- 사라진 우승 트로피 — 시상식 직전 사라진 컵을 찾는 가벼운 추리극.
- 파도가 멈춘 지도 — 지도 한 줄 때문에 흐름을 잃은 섬의 모험담.
- 퇴근길의 작은 탐사선 — 길을 잃은 조사 로봇과 마지막 근무를 마친 사람의 근미래 이야기.
- 한 장 남은 필름 — 마지막 사진 한 장을 남겨 둔 모녀의 여행.

도서관의 AI 소설에서 기존9편과 새8편, 총17편을 읽을 수 있어요. 기존 책 ID는 바꾸지 않고 새 작품에77~84를 사용해 독서 진도를 유지해요. 서버 동기화 SQL을 이미 설치했다면 [새 작품 등록 SQL](supabase/ai-books-20261123.sql)을 한 번 실행해 새 작품의 독서 미션·완독 포인트도 연결해요. 처음 설치한다면 갱신된 `supabase/sync.sql`에 이미 포함돼 있어요.


## 실행하기

- 최신 디자인은 `Reading_app.html` 하나에 들어 있어요. 브라우저에서 직접 열거나 `node dev-server.js --local`로 실행해요(기본 포트5173).
- Android는 빌드할 때 같은 HTML을 자동으로 복사해요.
- 카카오 연결을 시험할 때는 `node preview-server.cjs`를 실행하고 `http://localhost:5174/`로 열어요. 다른5174 서버가 실행 중이면 먼저 종료해요.
- 카카오 서버 설정은 저장소 밖의 `%LOCALAPPDATA%/DDOKDOK/local-auth/kakao-config.json`에서 읽어요. 필드는 `restApiKey`, 선택 항목 `clientSecret`이에요. 환경 변수 `KAKAO_REST_API_KEY`, `KAKAO_CLIENT_SECRET`을 설정하면 파일 값보다 우선해요.
- 카카오 Developers에 등록할 개발용 Redirect URI는 `http://localhost:5174/auth/kakao/callback`이에요.
- 로컬 가입 여부·닉네임·목표·성향 답변은 같은 설정 폴더의 `kakao-users.json`에 저장해요. 키·Client Secret·회원 데이터는 Git에 올리지 않아요.
- GitHub Pages의 카카오 로그인과 회원정보 저장은 Supabase에 연결돼 있어요. 이메일·Google 가입은 로컬 화면 확인용이에요. 위 로컬 서버 설정은 이전 개발용 연결이며 배포 앱에는 사용하지 않아요.

## 출시 필수 기능: 커뮤니티 안전·연령·탈퇴

- 출시 대상은 **만13세 이상**이에요. 만13세는 둘러보기만, 회원가입·개인 기록 저장은 만14세부터 가능해요. 계정 연결 전에 기기에서 만 나이를 확인하고 숫자 대신 `14plus` 확인 여부·시각·안내 버전만 새로 서버에 저장해요. 이 확인은 신분증을 이용한 실제 연령 인증이 아니에요. 기존 나이 필드는 다음 회원정보 저장 때 `null`로 정리해요.
- 커뮤니티는 Supabase RPC로 실제 글·댓글·좋아요·투표를 저장해요. 이전 예시 게시글은 실제 피드와 섞지 않아요. 글·댓글 작성 전에 이용 규칙 버전과 동의 시각을 서버에 남겨요. 서버가 준비되지 않거나 요청이 실패하면 접수·저장 완료로 안내하지 않아요.
- 게시글·댓글·사용자 신고, 양방향 글/댓글 차단과 해제, 본인 글·댓글 삭제, 본인 글 수정, 운영자의 신고 검토·숨김/복원·참여 제한과 해제를 지원해요. 일시 제한은24시간이고, 무기한 제한도 해제할 수 있어요. 신고 수만으로 자동 제재하지 않아요. 운영자 권한·작성자·공개 범위·제재·계정 상태는 서버에서 검사해요.
- 친구공개는 `ddok_friendships`의 실제 승인 관계가 있을 때만 공개돼요. 기존의 예시 친구 목록은 서버의 친구 관계로 취급하지 않아요. 실제 친구 연결 UI는 별도 연결 과제이며, 임시 친구에게 서버의 친구공개 글이 보인다고 안내하면 안 돼요.
- 회원 탈퇴는 최근15분 내 로그인한 본인만 실행해요. Edge Function이 토큰을 검증하고 계정 저장을 잠근 뒤, 계정 소유 Storage 파일을 Storage API로 삭제하고 Auth 계정을 삭제해요. DB의 FK·삭제 트리거로 프로필·설정·독서·포인트·커뮤니티 기록을 정리해요. 관리자 키를 앱에 넣지 않아요. 실패하면 완료로 안내하지 않으며, 부분 처리 뒤에는 다시 시도해야 해요.
- 이 기기의 토큰·계정별 기록·충돌 사본은 탈퇴 성공 뒤 지워요. 다른 기기는 인증 실패를 확인했을 때 해당 계정의 로컬 사본을 정리해요. 기기가 오프라인이면 즉시 원격 삭제할 수 없어요. 직접 내려받거나 외부에 공유한 사본·서비스 백업과 로그까지 즉시 삭제된다고 보장하지 않아요.
- 운영자: **팀 갤럭시**. 운영 문의·이의신청: **team.ddokdok@gmail.com**. 메일은 사용자가 직접 보내며 앱이 자동 접수한 것처럼 안내하지 않아요.
- 공개 문서: [이용 규칙](community-rules.html), [탈퇴·삭제 요청](delete-account.html), [개인정보처리방침 초안](privacy-policy.html). 개인정보 문서의 서버 국가·리전·수탁/국외 처리 세부사항·백업/로그 보유 기간은 운영 설정 확인 전이므로 **출시 확정본이 아니에요**.
- 스토어 콘텐츠 등급은 Play Console의 IARC 설문 결과로 정해요. 만13세 이상이라는 서비스 대상 설정을 IARC에서13세 등급을 받았다는 뜻으로 쓰지 않아요. 도서 본문·AI 소설과 UGC를 포함해 설문에 답해야 해요.

### Supabase 설치·배포

코드를 올리는 것과 운영 서버에 설치하는 것은 별개예요. 아래 작업을 마쳐야 새 서버 기능이 작동해요. 기존 로그인은 새 RPC 미설치 때 기존 경로로 유지하지만 신고·새 커뮤니티 저장은 성공으로 가장하지 않아요.

1. SQL Editor에서 기존 [sync.sql](supabase/sync.sql)을 설치한 뒤 [community.sql](supabase/community.sql)을 실행해요. 회원 기본 테이블이 없다면 생성하고, 기존 테이블에는 본인 접근 정책·계정 삭제 트리거를 적용해요. 재실행할 수 있어요. 먼저 기존 정책/스키마와 호환되는지 확인해요.
2. [delete-account Edge Function](supabase/functions/delete-account/index.ts)을 배포해요. CLI가 연결돼 있다면 `supabase functions deploy delete-account --project-ref zgsodnnlblfnrbcwatvs --no-verify-jwt`로 배포해요. 새 publishable key를 지원하기 위해 Edge 게이트 대신 함수 안의 Auth `/user` 호출로 사용자 토큰을 검증해요. `SUPABASE_URL`·`SUPABASE_SERVICE_ROLE_KEY`는 서버 환경에만 두고 채팅·앱·Git에 넣지 않아요.
3. 필요하면 서버의 `DDOK_ALLOWED_ORIGINS`에 허용할 Origin을 쉼표로 지정해요. 기본은 `https://jisoo0222.github.io,null`이에요. `null` Origin을 허용해도 인증 토큰 없이 삭제할 수 없어요. 출처 확인만으로 권한을 부여하지 않아요.
4. 운영에 사용할 **실제 똑독 회원 UUID**를 확인하고 SQL Editor에서 `insert into public.ddok_moderators(user_id) values ('운영자-회원-UUID') on conflict do nothing;`으로 운영자를 지정해요. 예시 UUID를 그대로 실행하지 않아요. 앱의 닉네임·로컬 플래그·사용자 메타데이터만으로 운영자가 되지 않아요. 해제는 같은 테이블의 해당 행을 삭제해요.
5. 운영 계정의 커뮤니티에서 **신고 관리**를 열어 처리해요. 일반 계정에서는 버튼을 숨기며, RPC를 직접 호출해도 권한을 검사해요. 신고 목록은 대기/검토 완료를 포함한 최근100건을 보여 줘요. 서버에는 처리 사유·운영자·시각을 기록해요.
6. 실제 서로 다른 테스트 계정으로 신고·차단·비공개·본인 삭제·운영 제재를 확인해요. 별도 폐기용 계정으로 탈퇴 후 Auth·DB·Storage와 기기 캐시 삭제를 확인해요. 실제 서버 배포/기기 테스트 전에는 출시 완료로 기록하지 않아요.

### 로컬 검증

앱에는 외부 런타임 라이브러리를 추가하지 않았어요. SQL 권한 검증에만 별도 임시 폴더에 설치한 `@electric-sql/pglite`를 사용해요. 이 도구와 테스트 데이터는 APK/HTML에 들어가지 않아요.

- `node tests/check-app-syntax.cjs` — 포함된 JavaScript 구문 검사.
- `node tests/delete-account.test.cjs` — Node24에서 Edge 인증·다른 계정 지정 거절·파일 선삭제·실패 처리·CORS 검증.
- `node tests/community-db.test.cjs <PGlite 설치 경로>` — 실제 PostgreSQL의 역할·RLS·RPC로 공개 범위·작성자 권한·차단·운영 권한·제재·삭제를 검증해요.
- `node tests/serve-community-fixture.cjs <PGlite 설치 경로>` — `http://127.0.0.1:5199/`의 격리된 브라우저 검증 화면. 운영 Supabase와 사용자 계정에 연결하지 않아요. 종료는 해당 테스트 프로세스에서만 해요.

## 독서 기록 동기화 연결하기

1. 기존 회원정보 SQL(`profiles`, `member_settings`)을 설치한 Supabase 프로젝트의 **SQL Editor → New query**를 열어요.
2. [supabase/sync.sql](supabase/sync.sql) 파일 전체를 복사해 실행해요. 기존 기록을 지우지 않으며 다시 실행해도 돼요.
3. 배포된 `Reading_app.html`을 새로고침하고 카카오로 로그인해요. 추가 비밀 키나 별도 서버는 필요하지 않아요.
4. 책을 읽고 문장·책갈피·메모를 남긴 뒤, 마이페이지 아래 **기록 동기화 · 저장됨**을 확인해요. 다른 브라우저에서 같은 카카오 계정으로 로그인하면 기록을 불러와요.

SQL을 실행하기 전에도 회원 로그인은 유지돼요. 기록은 기기에 보관하고 동기화를 재시도하며, 포인트 구매는 서버 준비 뒤에 할 수 있어요. 실행 후 마이페이지의 동기화 버튼을 누르면 바로 다시 연결해요.

- 동기화 범위: 읽는 책과 마지막 위치, 완독·일별 기록, 책갈피·형광펜·코멘트·책 위 메모, 내보낸 문장, 찜한 책·책장 배치, 만든 문구와 적용 설정, 서버 포인트·구매 내역이에요.
- 로그인·변경 뒤에 저장하고, 홈·마이페이지에서는 30초마다 서버 변경도 확인해요. 기록을 편집 중이거나 읽는 도중에는 다른 기기의 화면으로 갑자기 바꾸지 않아요.
- 연결이 끊기면 계정별 기기 보관함에 변경과 미션 신청을 남겨요. 같은 날짜 안에 다시 연결되면 전송해요. 지난 날짜의 미션은 소급 적립하지 않으며 독서 기록은 보존해요. 포인트 구매는 온라인에서 서버가 확인한 뒤 완료해요.
- 동시에 다른 기기에서 수정하면 어느 기록을 사용할지 물어요. 두 기록 전체를 자동으로 합치지는 않아요. 선택하지 않은 사본은 이 기기 `ddok_sync_v1:<회원 ID>:conflict-backup` 키에 보관해요. 충돌 안내를 닫았다면 마이페이지 동기화 버튼으로 다시 열 수 있어요.
- 기기의 예전 포인트·구매 표시를 서버 잔액으로 가져오지 않아요. 포인트는 서버 장부에서 새로 계산해요. 가격·하루 최대300P·하루 미션 중복·같은 물품 중복 구매·잔액은 서버에서 검사해요. 구매와 차감은 한 트랜잭션으로 처리해요.
- 읽기 미션은 현재 앱의 실제 본문 ID·페이지 범위·목표와 서버에 기록된 독서일을 확인해요. 공유·토론·코멘트 적립은 현재 앱이 보내는 활동 신호를 받아요. 포인트 RPC는 새 커뮤니티 글 원본이나 외부 공유 완료를 서버에서 독립적으로 검증하지 않아요.
- 공개 커뮤니티는 개인 기록 동기화와 별도로 `community.sql`을 설치해 연결해요. 친구 찾기는 기존 임시 예시 모드이며 서버의 친구 관계로 취급하지 않아요. 회원 프로필 사진은 기존 회원정보 저장을 사용해요.
- 이번에 추가한 개인 기록 테이블은 RLS로 본인만 조회할 수 있어요. 기록 수정·포인트·구매는 회원 ID를 입력받지 않는 인증된 서버 함수로 처리해요. 관리자 키를 앱에 넣지 않아요.

앱·SQL을 함께 유지해요. 본문이나 문구점 가격을 바꾸면 `ddok_books`·`ddok_catalog`의 설치 SQL도 갱신해야 해요. 한 계정의 독서 기록 문서는 최대5MiB이며, 현재 포인트 내역 화면은 최근500건 안에서 오늘 내역을 보여 줘요. 전체 포인트 장부는 서버에 남아요.
