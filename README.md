# 똑독(DDOKDOK) — AI 독서 습관 형성 앱

- 앱 바로가기: https://jisoo0222.github.io/reading/
- 앱 파일: `Reading_app.html` (HTML·CSS·JS가 모두 이 파일 하나에 있음)
- 작업 규칙: [AGENTS.md](AGENTS.md)

## AI 창작 단편

2026-11-23에 똑독 AI가 새로 쓴 단편8편을 추가했어요. 각6쪽이며 저자는 ‘똑독 AI’로 표시해요. 기존 출간 작품의 본문을 옮긴 글이 아닌 AI 예시 창작물이에요. 새 작품의 초기 열람 수는0이에요.

- 목요일의 빈 의자 — 늦게 끝나는 근무와 독서 모임 사이의 일상 이야기.
- 화성행 반품 택배 — 잘못 배달된 빗소리를 따라가는 우주 택배 기사의 SF.
- 어제의 날씨를 팝니다 — 놓친 운동회와 유리병에 담긴 날씨를 둘러싼 판타지.
- 302호의 연습곡 — 벽 너머에서 반복되는 열두 마디의 사연.
- 사라진 우승 트로피 — 시상식 직전 사라진 컵을 찾는 가벼운 추리극.
- 파도가 멈춘 지도 — 지도 한 줄 때문에 흐름을 잃은 섬의 모험담.
- 퇴근길의 작은 탐사선 — 길을 잃은 조사 로봇과 마지막 근무를 마친 사람의 근미래 이야기.
- 한 장 남은 필름 — 마지막 사진 한 장을 남겨 둔 모녀의 여행.

도서관의 AI 소설에서 기존9편과 새8편, 총17편을 읽을 수 있어요. 기존 책 ID는 바꾸지 않고 새 작품에77~84를 사용해 독서 진도를 유지해요. 서버 동기화 SQL을 이미 설치했다면 [새 작품 등록 SQL](supabase/ai-books-20261123.sql)을 한 번 실행해 새 작품의 독서 미션·완독 포인트도 연결해요. 처음 설치한다면 갱신된 `supabase/sync.sql`에 이미 포함돼 있어요.


## 실행하기

- 최신 디자인은 `Reading_app.html` 하나에 들어 있어요. 브라우저에서 직접 열거나 `node dev-server.js --local`로 실행해요(기본 포트5173).
- Android는 빌드할 때 같은 HTML을 자동으로 복사해요.
- 카카오 연결을 시험할 때는 `node preview-server.cjs`를 실행하고 `http://localhost:5174/`로 열어요. 다른5174 서버가 실행 중이면 먼저 종료해요.
- 카카오 서버 설정은 저장소 밖의 `%LOCALAPPDATA%/DDOKDOK/local-auth/kakao-config.json`에서 읽어요. 필드는 `restApiKey`, 선택 항목 `clientSecret`이에요. 환경 변수 `KAKAO_REST_API_KEY`, `KAKAO_CLIENT_SECRET`을 설정하면 파일 값보다 우선해요.
- 카카오 Developers에 등록할 개발용 Redirect URI는 `http://localhost:5174/auth/kakao/callback`이에요.
- 로컬 가입 여부·닉네임·목표·성향 답변은 같은 설정 폴더의 `kakao-users.json`에 저장해요. 키·Client Secret·회원 데이터는 Git에 올리지 않아요.
- GitHub Pages의 카카오 로그인과 회원정보 저장은 Supabase에 연결돼 있어요. 이메일·Google 가입은 로컬 화면 확인용이에요. 위 로컬 서버 설정은 이전 개발용 연결이며 배포 앱에는 사용하지 않아요.

## 독서 기록 동기화 연결하기

1. 기존 회원정보 SQL(`profiles`, `member_settings`)을 설치한 Supabase 프로젝트의 **SQL Editor → New query**를 열어요.
2. [supabase/sync.sql](supabase/sync.sql) 파일 전체를 복사해 실행해요. 기존 기록을 지우지 않으며 다시 실행해도 돼요.
3. 배포된 `Reading_app.html`을 새로고침하고 카카오로 로그인해요. 추가 비밀 키나 별도 서버는 필요하지 않아요.
4. 책을 읽고 문장·책갈피·메모를 남긴 뒤, 마이페이지 아래 **기록 동기화 · 저장됨**을 확인해요. 다른 브라우저에서 같은 카카오 계정으로 로그인하면 기록을 불러와요.

SQL을 실행하기 전에도 회원 로그인은 유지돼요. 기록은 기기에 보관하고 동기화를 재시도하며, 포인트 구매는 서버 준비 뒤에 할 수 있어요. 실행 후 마이페이지의 동기화 버튼을 누르면 바로 다시 연결해요.

- 동기화 범위: 읽는 책과 마지막 위치, 완독·일별 기록, 책갈피·형광펜·코멘트·책 위 메모, 내보낸 문장, 찜한 책·책장 배치, 만든 문구와 적용 설정, 서버 포인트·구매 내역이에요.
- 로그인·변경 뒤에 저장하고, 홈·마이페이지에서는 30초마다 서버 변경도 확인해요. 기록을 편집 중이거나 읽는 도중에는 다른 기기의 화면으로 갑자기 바꾸지 않아요.
- 연결이 끊기면 계정별 기기 보관함에 변경과 미션 신청을 남겨요. 같은 날짜 안에 다시 연결되면 전송해요. 지난 날짜의 미션은 소급 적립하지 않으며 독서 기록은 보존해요. 포인트 구매는 온라인에서 서버가 확인한 뒤 완료해요.
- 동시에 다른 기기에서 수정하면 어느 기록을 사용할지 물어요. 두 기록 전체를 자동으로 합치지는 않아요. 선택하지 않은 사본은 이 기기 `ddok_sync_v1:<회원 ID>:conflict-backup` 키에 보관해요. 충돌 안내를 닫았다면 마이페이지 동기화 버튼으로 다시 열 수 있어요.
- 기기의 예전 포인트·구매 표시를 서버 잔액으로 가져오지 않아요. 포인트는 서버 장부에서 새로 계산해요. 가격·하루 최대300P·하루 미션 중복·같은 물품 중복 구매·잔액은 서버에서 검사해요. 구매와 차감은 한 트랜잭션으로 처리해요.
- 읽기 미션은 현재 앱의 실제 본문 ID·페이지 범위·목표와 서버에 기록된 독서일을 확인해요. 공유·토론·코멘트 적립은 현재 앱이 보내는 활동 신호를 받아요. 공개 커뮤니티 서버는 아직 연결하지 않아 공개 글 원본이나 실제 공유 완료를 서버에서 독립적으로 입증하는 단계는 아니에요.
- 공개 커뮤니티·친구 찾기는 이번 동기화 범위에 포함하지 않아요. 친구 찾기는 기존 임시 예시 모드예요. 회원 프로필 사진은 기존 회원정보 저장을 사용해요.
- 이번에 추가한 개인 기록 테이블은 RLS로 본인만 조회할 수 있어요. 기록 수정·포인트·구매는 회원 ID를 입력받지 않는 인증된 서버 함수로 처리해요. 관리자 키를 앱에 넣지 않아요.

앱·SQL을 함께 유지해요. 본문이나 문구점 가격을 바꾸면 `ddok_books`·`ddok_catalog`의 설치 SQL도 갱신해야 해요. 한 계정의 독서 기록 문서는 최대5MiB이며, 현재 포인트 내역 화면은 최근500건 안에서 오늘 내역을 보여 줘요. 전체 포인트 장부는 서버에 남아요.
